# KinoTV 积分中心（`/wallet`）设计规范

> 适用页面：用户端 `GET /wallet`（积分余额 / 充值商品 / 积分流水）。
> 约束来源：`web/src/styles/globals.css`（唯一 token 来源）、登录页 `web/src/features/hosted-auth/login-page.css`（已定型的玻璃语言）、后台积分域 `backend/internal/auth/credit_model.go`（真实字段）。
> 本文只描述「应该长什么样」，不含实现代码。

---

## 1. 设计立场

**一句话主张：这是一块「仪表盘读数 + 台账」，不是一张促销海报。**

余额是用户每次点「生成」前唯一会瞄一眼的数字，所以这一页的主角只有一个——**剩余积分**，其余全部退居支撑位；充值是它的下一步动作，流水是它的账目凭据。整页用近黑单色强调 + 1px 发丝描边 + 分层面料（luminance stepping），让「数字」和「余额变动」成为唯一的视觉事件，而不是让颜色和渐变来制造热闹。

**与登录页 / 创作台如何统一**——统一的是**材质语言**，不是底色：

- 沿用登录页已定型的玻璃面：卡片 22px 圆角（`--r-wide-tight`）、`linear-gradient(180deg, rgba(255,255,255,0.062), rgba(255,255,255,0.018))` 的顶部高光、`inset 0 1px 0 rgba(255,255,255,0.06)` 内高光、外层深投影。
- 沿用创作台的「一个高对比动作」原则：整页只有主 CTA 用白底高光实心块，其余按钮一律 ghost / 描边。
- **底色跟随应用主题，不像登录页那样强制常暗。** 登录页是产品门面（一次性、可控光环境），积分页是高频工作页，用户在亮色工作台里点进来不该被拉到另一个色温。明色下用 `--surface` / `--card-surface` 面料分层，暗色下走 `--elevation-hairline` 与白色微影抬升——两套都由同一批 token 自动级联，不新增分支。
- 字形继续分工：标题 `--font-display`（Space Grotesk，「仪器面板」气质），金额与流水数字 `--font-mono`（Geist Mono，等宽对齐），正文 `--font-sans`（Geist）。

## 2. 主参考设计系统

### 主参考：**Vercel**（`design-systems/vercel/DESIGN.md`）

选它不是因为「看起来像」，而是**三处硬对齐**，其余候选都对不上：

| 对齐点 | KinoTV 现状 | Vercel 规范 |
|---|---|---|
| 正文字体 | `--font-sans` = Geist，`--font-mono` = Geist Mono | Geist 就是 Vercel 的自有字系（Geist Sans + Geist Mono） |
| 强调色 | `--accent` = `--workspace-accent` = `#171717`（近黑单色，无品牌彩） | 「Near-pure white canvas with `#171717` text」——同一个 `#171717`，同为单色克制 |
| 描边技法 | 已有 `--elevation-hairline: inset 0 0 0 1px rgba(255,255,255,0.085)` | Vercel 招牌的 shadow-as-border：`box-shadow: 0 0 0 1px rgba(0,0,0,0.08)` 代替传统 border |

**为什么不是 Linear**：整套系统建立在**靛紫强调色**上（`#5e6ad2` / `#7170ff` / `#828fff`），而靛紫正是 `anti-ai-slop.md` 第 1 条 P0 明令禁止的色（`#6366f1 #4f46e5 #4338ca #3730a3 #8b5cf6 #7c3aed #a855f7` 同族）。照搬 Linear 等于第一眼就把 KinoTV 打成 AI 模板；而且 KinoTV 的 accent 本来就是单色，引入紫是给自己加一个不存在的品牌色。

**为什么不是 Raycast / Arc / Supabase**：Raycast 偏 macOS 玻璃拟态（装饰性光晕重，与本页「台账」气质不符）；Arc 是消费级玩趣调性；Supabase 是暗色 + 青绿，与 KinoTV 的 Space Grotesk + 近黑单色不同宗。

### 次参考：**Linear**（只取结构纪律，明确丢弃其配色）

采用它的四条**结构性**规则，因为它们与登录页已经落地的做法一致：

1. 暗色抬升靠**背景明度步进**（`rgba(255,255,255,0.02 → 0.04 → 0.05)`），不靠投影；
2. 描边恒为**半透明白 hairline**（`rgba(255,255,255,0.05–0.08)`），不用实心深色边框——登录页的 `--auth-hairline: rgba(255,255,255,0.09)` 已经是这个值；
3. 三字重体系 **400 读 / 510 强调 / 590 announce**，上限 590，永不 700；
4. **强调色只给交互态，不做装饰**。

**丢弃**：Linear 的靛紫 accent，以及它「暗色原生」的强制前提（本页跟随主题）。

### 从 `craft/` 摘出的硬性规则与 anti-ai-slop P0 逐条落地

`anti-ai-slop.md` 的七宗罪是 P0（linter 会拦），逐条给出本页的满足方式：

| # | P0 禁项 | 本页如何满足 |
|---|---|---|
| 1 | 默认 Tailwind indigo 作强调色 | 全页零硬编码 hex，唯一强调色是 `--accent`（近黑 `#171717`）；暗色场景强调用 `--auth-accent`（`rgba(147,197,253,0.8)`，恰好落在 Vercel 的 Ring Blue `rgba(147,197,253,0.5)` 同族）。充值主 CTA 用白底高光实心，不用彩色填充 |
| 2 | hero 上的两段式「信任渐变」（紫→蓝 / 蓝→青 / 靛→粉） | 余额卡**禁止任何渐变填充**。靠单层面料 + 底部一道 hairline 分层，纵深由 `--elevation-card` 与明度差制造 |
| 3 | emoji 当功能图标 | 权益/状态图标一律 lucide，`strokeWidth={1.75}`、`currentColor`——项目既有惯例（`callout.tsx` 即 `strokeWidth={1.75}`）。流水类型图标同理 |
| 4 | display 文本上系统无衬线 | 页面标题、余额数字、区块标题一律 `var(--font-display)`；`font-family: system-ui` 单用视为缺陷 |
| 5 | 「圆角卡 + 左侧彩色竖条」AI 仪表盘瓦片 | 明令禁止。选中态改用**边框对比度 + 角标文字**，不用左侧色条 |
| 6 | 编造指标（10× faster / 99.9% uptime） | 不写任何未由服务端返回的比率。金额、积分、折扣、有效期全部来自 `CreditWalletView` / `CreditLedgerEntryView`；拿不到就显示真实值或缺省说明 |
| 7 | 填充文案（lorem / feature one / placeholder） | 空态写具体引导句（见 §5），沿用项目语言（如「还没有积分记录」），不留占位文本 |

补充 `craft/` 的量化约束，本页必须满足：

- **强调色每屏 ≤2 次可见使用**（`color.md`）：本页配额 = ① 充值主 CTA ② 余额数字。再想加第三个强调色元素，就是在稀释主角。
- **`var(--accent)` 出现 ≤6 次**（`anti-ai-slop.md` P1），`raw hex` 仅允许出现在 `:root`（P1：正文区裸 hex >12 个即视为未使用 token）。
- **配色占比**（`color.md`）：中性色 70–90%，强调 5–10%，语义色（success/warn/danger）0–5%，effect（渐变/光晕）<1%。本页是「数据页」，语义色只用于流水状态与余额不足，**不得**用来给充值卡上色。
- **字号可见层级 ≤3 档**在首屏以上（`typography.md`）：首屏只有「余额数字 / 区块标题 / 说明文字」三档。
- **CJK 覆盖**（`typography.md`，非可选）：中文标题行高 ≥1.3（拉丁 display 的 1.0–1.2 会让中文行贴字），且**中文不加负字距**。余额数字是拉丁数字，可保留最紧的字距。
- **决策上限**（`laws-of-ux.md` Hick's Law / Choice Overload）：充值档位一屏 **3–4 档，且恰好一个标为推荐**；超过 5 档必须折叠。
- **分组间距**（`laws-of-ux.md` Proximity）：组内 8–12px，组间 32–48px。**等距排版 = 没有分组**，这是本页最容易犯的错。

## 3. 页面结构与布局

### 外壳复用

页面必须复用既有外壳，不自建 header：

- `WorkspacePage`（`components/layout/workspace-page.tsx`）：`<main class="app-user-content app-workspace-scroll">`，默认内边距 `px-3 py-3 sm:px-4 xl:px-5`。
- `PageHeader`：`title="积分中心"`，`description` 一句话说明计费口径，`meta` 放账号名，`actions` 放次要动作（刷新/明细导出）。`app-page-header` 自带 sticky + `backdrop-filter: blur(var(--glass-blur)) saturate(var(--glass-saturate))`，高度 `--page-topbar-h`（64px），层级 `--z-toolbar`（30）——余额卡滚动到它下面时必须被正确遮挡，斑驳透出即为缺陷。
- `TableSurface` 承载流水表，`CollectionGrid` 承载充值商品，`PaginationBar` 承担流水分页，`WorkspaceState` / `WorkspaceErrorState` / `WorkspaceLoadingState` 承担三态，`Callout` 承担内联提示。

### 三级信息层级（信息优先级即视觉权重）

**Zone A — 余额区（主角，占首屏视觉重心）**

单张余额卡，左对齐大字读数。信息优先级从高到低：

1. **剩余积分**（唯一的视觉主角，最大字号）
2. 主 CTA「充值」（紧跟读数右侧或下方，视线不折返）
3. 累计获得 `lifetimeIn` / 累计消耗 `lifetimeOut`（次级读数，成对出现，等宽对齐）
4. 更新时间 `updatedAt` 与有效期/冻结说明（最弱，`--fs-label` 级，`text-foreground/58`）

余额为 0 时，把「充值」提到读数正下方并保留位置（不跳版），读数变 `--fs-title` 而非 display——**零余额是状态，不是错误**（`credit_model.go` 明确：账户不存在时给零余额，不报错）。

**Zone B — 充值区（决策区）**

- 区块标题 + 一句口径说明（「1 元 = N 积分」这类换算必须写在这里，且来自服务端商品数据，不前端硬编码）。
- 商品卡网格：`CollectionGrid`（`grid-cols-1 sm:grid-cols-[repeat(auto-fill,minmax(248px,1fr))]`），一屏 3–4 档。
- 恰好一档标推荐（`Von Restorff`）：用**文字角标 + 边框对比**表达，不用左侧色条、不用彩色填充。
- 每档可展示：面额、实付价格、到账积分、赠送积分（`TOPUP` 与 `TOPUP_GIFT` 是两个来源，分开写）、有效期。**不展示编造的折扣率**。
- 支付渠道选择与优惠券入口放在商品卡之下的**结算条**，与商品网格分离，避免把决策和付款混成一层。

**Zone C — 流水区（凭据区）**

- 全宽 `TableSurface`，列固定为：**时间 / 类型 / 说明 / 变动 / 变动后余额 / 状态**。
  - 「类型」映射 `kind`：`TASK_CHARGE` 任务扣费、`TASK_REFUND` 任务退回、`TOPUP` 充值到账、`TOPUP_GIFT` 赠送积分、`ADMIN_ADJUST` 后台调整。
  - 「变动」直接按 `amount` 符号渲染 `+` / `−`（`credit_model.go` 已定：**符号即方向，前端不再按 kind 二次判断**）。
  - 「变动后余额」= `balanceAfter`，等宽右对齐——这是用户对账的锚点，不能省。
  - 说明取 `note`；有 `refType` / `refID` 时说明列附一个可跳转的关联入口（如任务详情），无关联则纯文本。
- 列头与列值**必须对齐成列**：金额列右对齐 + `tabular-nums`，否则「比较两笔扣费金额」这个唯一真实任务做不了。
- 区块顶部放筛选（类型 / 时间范围）与分页条；筛选态用项目既有 chip 语言。

### 栅格与响应式

- 桌面（≥1280px）：内容列居中收敛（与 `settings-pane` 同为居中单列，`mx-auto`），Zone A 全宽；Zone B 3–4 列自适应；Zone C 全宽表格。
- 平板（768–1280px）：Zone B 落 2 列；流水表保留列语义，允许横向滚动而不折行成三段。
- 移动（<768px）：Zone B 单列；流水**从表格降级为行**（两行式：主行「类型 + 变动金额」，副行「时间 + 变动后余额」），不用横向滚动表格。
- 纵向节奏（Proximity）：Zone 内元素间 `--space-2`~`--space-3`；Zone 与 Zone 之间 `--space-8`~`--space-12`。**Zone 间不得用卡片套卡片**——沿用设置页的既有决策「用连续 section 表达层级，不用卡片套卡片」（`globals.css` 注释）。

## 4. 视觉规格

### 面料与分层

| 用途 | Token | 说明 |
|---|---|---|
| 页面底 | `--workspace-content`（= 页面底色） | 与导航同底，不额外加底色 |
| 余额卡 / 商品卡 / 表格容器 | `--surface`（明 `--color-neutral-0`；暗 `--surface-card: rgba(255,255,255,0.035)`） | 卡片是「面料」，不是「色块」 |
| 次级读数底 | `--color-surface-secondary`（= `--bg-secondary` = `--color-neutral-50`） | 累计获得/消耗的承托面 |
| 悬停 | `--surface-hover`（`rgba(17,17,17,0.05)`）/ `--library-surface-hover` | 整卡可点时用背景变化，不用位移 |
| 强调软底 | `--accent-soft`（`--workspace-accent-soft`, `rgba(17,17,17,0.07)`） | 选中/激活态 |

### 描边与圆角

- 默认描边：`--workspace-border`（`rgba(17,17,17,0.14)`）或语义 `border-border`。
- 暗色描边：改用 `--elevation-hairline`（`inset 0 0 0 1px rgba(255,255,255,0.085)`）——**暗色下不用实心深色边框**（Linear 规则，项目已有此 token）。
- 选中/推荐态：描边提到 `--workspace-border-strong`（`rgba(17,17,17,0.22)`）或 `border-foreground/45`（计费页既有写法），**不加左侧色条**。
- 圆角：卡片 `--r-2xl`（16px）～`--r-wide-tight`（22px，与登录卡一致）；内部字段/按钮 `--r-lg`（12px，与登录页输入框一致）；徽章/胶囊 `--r-full`。**同一屏内不超过 3 档圆角**。

### 玻璃材质（沿用登录页定型的这一套，不重新发明）

暗色场景（余额卡在暗色主题下、浮层）：

```
背景: linear-gradient(180deg, rgba(255,255,255,0.062), rgba(255,255,255,0.018))
描边: 1px rgba(255,255,255,0.1)
内高光: inset 0 1px 0 rgba(255,255,255,0.06)
投影: 0 40px 90px rgba(0, 0, 0, 0.5)
圆角: 22px
```

模糊参数一律走 token：`backdrop-filter: blur(var(--glass-blur)) saturate(var(--glass-saturate))`，其中 `--glass-blur: 10px`、`--glass-saturate: 112%`、`--glass-alpha: 0.94`、`--glass-border-alpha: 0.78`。**禁止在组件里写字面 blur/saturate 值**（`globals.css` 注释已明确这一约定）。

### 字体与字号

| 元素 | Token | 字号 | 附加 |
|---|---|---|---|
| 页面标题 | `--font-display` | `--fs-title`（22px） | `letter-spacing: -0.01em`（`app-page-header-title` 既有值） |
| 余额数字 | `--font-display` | `--fs-display`（36px） | `tabular-nums`；拉丁数字可紧字距，若有中文单位则 `0` |
| 区块标题 | `--font-display` | `--fs-heading-lg`（18px） | 中文行高 ≥1.3 |
| 卡片面额/价格 | `--font-display` | `--fs-title`（22px） | `tabular-nums` |
| 正文 / 说明 | `--font-sans` | `--fs-body`（14px）/ `--fs-caption`（12px） | 行高 1.5–1.6；中文段落 1.7–1.8 |
| 流水数字、订单号、时间 | `--font-mono` | `--fs-caption`（12px） | `tabular-nums`，右对齐 |
| 标签 / 角标 | `--font-sans` | `--fs-label`（11px）/ `--fs-tiny`（10px） | `letter-spacing: 0.02em`；全大写必须 `0.06em`–`0.1em` |

字重只用三档：400（正文）、500/510（标签与按钮）、600（标题与金额）。**不用 700。**

### 语义色

- 仅三处允许出现语义色：流水「状态」列、余额不足提示、支付失败/成功提示。
- 取 `--color-status-success` / `--color-status-warning` / `--color-status-error`（底层 `--palette-status-*`）。**不复用 AntD 预设色**（`gold` / `green` / `blue` / `red`）——那是当前计费页最刺眼的问题之一，见 §8。
- 入账/出账**不能只靠红绿**（`accessibility-baseline.md` 禁止颜色单通道）：必须同时有 `+` / `−` 符号（数据层已带符号）与文字标签。

### 动效

- 时长取 `--motion-instant`（120ms）用于悬停/焦点，`--motion-state`（180ms）用于状态切换，`--motion-panel`（240ms）用于区块进出。**任何非跨屏过渡不超过 500ms**（`animation-discipline.md`）。
- 缓动用 `--ease-product-enter`（`cubic-bezier(0.16, 1, 0.3, 1)`）——登录页已用此曲线。
- 余额刷新时可做一次 `count-up`，**一次性、≤600ms、不循环**；`prefers-reduced-motion` 下直接落终值。
- 禁止：装饰性光带/噪点、循环 shimmer 超过内容到达时间、把动效作为状态变化的唯一信号。

## 5. 状态覆盖

`state-coverage.md` 的五态是硬要求，「只画了有数据的样子」是最典型的失分项。本页三个 Zone **各自独立**拥有五态。

### 加载

- 余额区用**骨架**（不是 spinner），骨架保持真实版式（一个 display 级长条 + 两条次级短条），避免「加载完成时页面跳一下」。
- 阈值：0–300ms 不显示指示；>300ms 显示骨架；**>15s 追加「比预期慢」文案 + 重试**（`state-coverage.md`）。
- 骨架静止。`prefers-reduced-motion` 下不闪烁。

### 空

- **首用空（无流水）**：`WorkspaceState` + `--font-display` 标题「还没有积分记录」+ 一句价值说明 + 主 CTA 直达充值。空态是引导位，不是留白。
- **无商品**：绝不能空白。显示「暂无可购买的套餐」+ 说明「请联系客服开通」+ 支持入口。
- **筛选无结果**：**回显查询条件**（如「近 7 天 · 充值」），给「清除筛选」，永远不留真空。
- **零余额 ≠ 空态**：余额 0 仍完整渲染余额卡（见 §3 Zone A）。
- **错误不得伪装成空**（`state-coverage.md` 明确禁止 error-as-empty）。

### 错误

三个 Zone 独立失败、独立恢复，**不得用一个页面级错误吞掉全部**：

- 余额失败 → 余额卡内联错误 + 「重新加载」，充值区和流水区照常工作。
- 流水失败 → 表格区内联错误 + 重试，余额照常显示。
- 错误文案回答三问（`state-coverage.md`）：**发生了什么 / 为什么（可知时）/ 用户能做什么**。禁止「出了点问题」这类无信息文案；服务端返回的中文原文要原样透出（项目既有约定：`errorMessage()` 只在本地位缺时兜底）。

**重试纪律**：首次点击立即重试；第 2、3 次退避 2s / 4s；3 次失败后把「重试」换成「联系支持」+ **可复制的错误 ID**，并在重试后显示「上次尝试：Xs 前」。

### 部分失败

- 余额成功 + 流水失败：余额与充值区完全正常，只有流水区降级——**这是本页最重要的一条**，用户的钱不该因为账目接口抖动而看不到。
- 支付回调未落地：订单/流水显示**「待确认」而不是「失败」**，并给出「支付完成后自动更新」的说明。把未确认写成失败会造成重复付款。
- 赠送积分与充值积分分开到账时：两笔各自独立渲染（`TOPUP` + `TOPUP_GIFT`），不合并成一条含混的「+120」。

### 余额不足（`CodeInsufficientCredits = 40201`）

- 就地内联提示（`Callout tone="warning"`），文案说明缺多少（差额由服务端给）与「充值后立即生效」。
- 提示内直接给充值入口，锚点跳到 Zone B，**不清空用户已填的创作输入**（`state-coverage.md`：错误必须保留用户输入）。
- 禁止用 modal 打断；禁止把余额不足渲染成页面级错误。

### 超长 / 边界

- 流水用 `PaginationBar` 分页（默认 20/50/100），**不用无限滚动**——台账需要可回看的位置感。
- 订单号 / `refID` 超长：`truncate` + `title` 全文，或等宽字体的「前 8 位 … 后 4 位」；**不换行撑破列宽**。
- 金额极大（万亿级）：等宽 `tabular-nums` 下测列宽；不缩字号、不省略为 `1.2k`（台账要精确值）。
- `note` 达 255 字符上限（后端已截断）：说明列限定 2 行 + `title` 全文。
- 时间跨年 / 时区：统一走项目 `formatDateTime`，不本地手写格式化。
- 筛选出 10 万条：分页总数与页码胶囊保持可用（复用 `pageItems` 省略号逻辑）。

## 6. 无障碍（目标 WCAG 2.2 AA）

**对比度（门槛，不是目标）**

- 正文（≤16px）对背景 **≥4.5:1**；大文本（≥24px 或 ≥18.5px 粗体）**≥3:1**；UI 组件与相邻面 **≥3:1**；焦点指示对相邻态 **≥3:1**。
- 注意 18px 常规字**不算**大文本（要 4.5:1）——`text-foreground/58` 这类半透明前景必须实测，不靠感觉。
- 阈值是**闭区间**：恰好 4.5:1 通过，2.999:1 不通过。

**焦点可见**

- 用 `:focus-visible`，**绝不允许 `outline: none` 而不给替代**（等于同时违反 1.4.11 / 2.4.7 / 2.4.13）。
- 焦点环用 `--auth-accent` 同族色（暗）或 `--foreground`（明），并保证 3:1。

**键盘可达**

- 商品卡是**单选语义**（radio group）：方向键在档位间移动，Tab 只进出组一次。
- 筛选、分页、关联跳转全可键盘触达；分页按钮已有 `aria-label`（`PaginationBar` 既有实现，沿用）。
- 焦点顺序与视觉顺序一致；sticky header 不得挡住获得焦点后滚入的元素。

**触控目标**

- 主体按钮与商品卡 **≥44×44 CSS px**（AAA 承诺）；图标按钮不得低于 **24×24**（AA 底线），密集工具栏可依据「间距例外」成立，但该例外不能用来给过小的主操作开脱。

**动效降级**

- `prefers-reduced-motion: reduce` 下剥离一切位移/缩放/旋转，仅保留 opacity 与颜色变化。
- 项目已有 `--motion-scale`（1 / 0.3 / 0）与 `.no-motion` 机制，**直接复用，不新增媒体查询分支**。
- 余额 count-up、充值成功反馈属于增强；降级时必须仍有静态信号（数值本身、文案标签）。

**屏幕阅读器**

- 余额更新与支付结果用 `aria-live="polite"` 播报，避免金额变化静默发生。
- 加载容器 `aria-busy="true"`（`WorkspaceLoadingState` 已带）。
- 入账/出账除颜色外要有可读文本（「充值到账 +500」），保证非视觉用户能区分方向。
- 表格用真实 `<table>` 语义（`th` / `scope`）而非 div 堆叠，让列头与数据关联成立。

## 9. 关键组件形态

### 9.1 余额卡

- 形态：横向单卡，左对齐读数，右/下为动作与次级读数。**不用居中大数字**（居中会把「读数」变成「庆祝」）。
- 层次：剩余积分（`--font-display`，36px，`tabular-nums`）→ 主 CTA（白底高光实心，`--r-lg`）→ 累计获得 / 累计消耗（成对，`--color-surface-secondary` 承托面，等宽）→ 更新时间（`--fs-label`，`text-foreground/58`）。
- 材质：跟随主题；暗色下用登录页同款玻璃（22px 圆角 + 顶部高光 + 0 40px 90px 深投影）。**卡内不出现渐变填充**。
- 无数据时给零余额，保持版式不跳。
- 刷新时一次性 count-up（≤600ms），降级直接落值。

### 9.2 充值商品卡

- 形态：竖版卡，占比最大的元素是**到账积分**（不是价格）——用户真正在买的是积分。
- 内容顺序：档位名 / 到账积分（大）/ 实付价格 / 赠送积分（单列一行，与到账分开）/ 有效期 / 选择动作。
- 推荐档：右上角文字角标 + 描边提升（`--workspace-border-strong`），**无左侧色条、无彩色填充**。
- 选中：描边对比 + 单主信号；卡可整块点击，但保留明确的选中语义（radio group）。
- 悬停：`--library-surface-hover` + 描边过渡（`--motion-state`），不做位移。
- 网格：`CollectionGrid`，一屏 3–4 档，超出折叠。

### 9.3 流水行 / 表

- 桌面：`TableSurface` 内真 `<table>`，列固定六列（时间 / 类型 / 说明 / 变动 / 变动后余额 / 状态），金额列右对齐等宽，时间用等宽小字号。
- 「类型」列：lucide 图标（1.75px stroke）+ 中文标签，图标只做**辨认辅助**，语义由文字承担。
- 「变动」列：`+500` / `−1200`，符号 + 语义色 + 文字可读（二者其一就够辨认，但符号必须有）。
- 行悬停：`--surface-hover`；可跳转行给整体可点 + 键盘焦点。
- 移动：降级为两行式行（主行类型 + 金额，副行时间 + 变动后余额），不做横向滚动表格。
- 空/错/加载三态就地区域内渲染，不顶掉整页。

### 9.4 空状态插画

- **不引入外部插画资源**。复用项目 `WorkspaceSignalIcon`（`components/ui/aceternity/workspace-signal-icon`，`variant="empty" | "error" | "loading"`），与 `WorkspaceState` 组合：图标 → `--font-display` 标题 → 一句说明（≤`42ch`，与既有 `max-w-[42ch]` 一致）→ 主 CTA。
- 首用空态（无流水）承担引导职责：标题 + 价值句 + 「去充值」；不是装饰性留白。
- 筛选无结果态：回显筛选条件 + 「清除筛选」，不用插画，用文字解决。
- 插画不做循环动效；一次性淡入即可。
